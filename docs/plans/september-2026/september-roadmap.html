The order that makes this possible

Early work removes the dependencies that would otherwise consume the month.

First / Organize

Joe + Ryan agree capacity and split ownership. Pool brand assets, configure shared tools and start the workspaces.

Then / Establish

Start publishing in Week 1. Build the website and mailing list while researching event feasibility and writing the app’s event spec.

Next / Commit

Choose an event after checking its constraints. Build and test the app experience, gather early feedback, and expand toward 30 friends.

Finally / Close

Secure event commitments, resolve release blockers, and prove the publishing process works repeatedly with multiple contributors.

Proposed dates depend on the Sep 11 scope review. Preserve promotion lead time when choosing the event date.

App relationship

EXIT: an approved event brief and commitment record. Public promotion begins when the team agrees the event is ready.

The shared event workspace

One event record, visible and editable by everyone doing the work.

Brief + boundaries

Audience, experience, date options, geography, capacity, budget limit and what makes an opportunity worth pursuing.

Work breakdown

Venue, labor/vendors, equipment, logistics, promotion, registration and app integration. Each component has one accountable owner.

EXIT: every required component has an owner and a status. Any remaining blocker is visible before the date is called locked.

The gate measures people with access to a usable app. Feedback guides the next release.

Baseline + rebrand

EXIT: 30 verified friends with working access, a release that passes the agreed checklist, and a running survey, meeting and feedback process.

The full development scope

Objective 02 includes new work, release quality and changes learned from users.

Search acceptance

Joe + Ryan try the latest search together. Agree representative tasks, record gaps and distinguish acceptable beta quality from later improvements.

P0/P1 triage

Review existing bugs this week. Proposed P0: a critical flow is unusable or data is at risk. P1: a core task fails with no reasonable workaround.

Map performance

Verify the recent performance work on target devices and representative maps. Record slowdowns and regressions against agreed acceptance criteria.

Events + opt-in

Build the approved event experience and newsletter signup integration. Carry the app rebrand and any remaining baseline gaps in the same estimate.

Feedback fixes

Reserve recurring development blocks for survey and interview findings. Implement the highest-impact changes and retest them with users.

RELEASE GATE: accepted search and map behavior, agreed event scope, no open P0/P1 release blockers and tested feedback fixes.

Survey + follow-up meetings

Objective 02 includes a repeatable way to learn from the people using the app.

Before rollout

Pilot the 30-question Google Form with two testers. Name the collection owner, link the response sheet and check the time to complete.

After use

Send after a meaningful session or failed first attempt, ideally within 24–48 hours. Send one reminder after three days if needed.

Follow-up meetings

Offer a 20-minute conversation to willing respondents. Proposal: 8–10 meetings across the cohort, including blocked and successful users.

From answer to fix

Review responses daily. Record the task, expected result, actual result and impact. Turn actionable findings into owned issues.

Close the loop

Review themes weekly, verify fixes with testers and record retest outcomes. Track survey and meeting status separately from the 30-friends gate.

EXIT: a working form, response tracker, completed user conversations and a prioritized backlog with evidence.

The event feature needs a crisp spec

Joe + Ryan settle the product relationship before committing to a build date.

Experience

Define how someone discovers 001, understands it, opens details and registers. Specify upcoming, unavailable and empty states.

Model + navigation

Define event versus place, the relationship to the map, and where the event hub lives. Record any new data model or migration work.

Scope decision

Compare a minimal event hub with fuller integration. A place-profile shortcut or external form remains an option to evaluate.

Acceptance + tests

Test navigation, event details, registration handoff, map/place relationships and failure states. Include regression coverage for the existing app.

Release review

Run a joint walkthrough and user feedback session. Record pass/fail against the spec before increasing the friend cohort.

PROPOSED DEFAULT: include an event hub in the 30-friends release. Change that condition only through an explicit product decision.

How we run the work

Focus blocks + accountable owners

Joe + Ryan provide all planned capacity. Assign the two founder roles on Sep 8.

Founder capacity

Proposal: ten two-hour blocks per founder each week. Joint sessions count against both people’s capacity.

Parallel work

The app lead covers development and feedback fixes. The event + brand lead owns event planning, the site and content production.

Brand capacity

The event + brand lead budgets three blocks for brand, four for events, two for joint work and one buffer. Batch simple posts and use the scheduler.

Protected capacity

App lead: protect two feedback-fix blocks and one buffer. The other seven include joint reviews. Count site and list engineering here too.

Friday review

Open the work itself: build, event commitments, published links and subscriber flow. Reassign or reschedule any work without a credible path.

Day blocks are proposed focus windows, not calendar bookings. Print the daily sheet before work. Joint decisions need both founders; execution needs one owner.

Decisions that control the schedule

Resolve these early enough to change the plan while time remains.

Sep 8 / Ownership

Name the app lead and event + brand lead. Confirm both founders’ availability, access and authority for event commitments.

Sep 9 / Brand cadence

Confirm channels, post frequency, newsletter format and the shared workflow. The 15-post plan is a starting proposal. Newsletter success means first issue created.

Sep 11 / App scope

Estimate app work alongside site/list build, content and event work. Keep feedback time free. Reduce complexity or revise dates if the two-person budget does not fit.

Before event lock

Confirm brand-establishment and promotion lead times. Move the event date if commitments or readiness cannot support them.

If capacity tightens

Reduce optional event scope and production complexity first. Protect P0/P1 and feedback time. If 15 posts still do not fit, agree a revised cadence explicitly.

A partial event page, tentative venue hold or unfinished feature stays visibly incomplete until its acceptance conditions pass.
