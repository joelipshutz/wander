# Live review, second feedback round

## Implementation plan

This extends REC-636/PR736 on the existing isolated review branch. User-reported passes from the prior round are retained: R1–R4, R7–R10, S2 and S3. R5/R6/R11/S1 have new changes. Deferred blocks remain untested rather than assumed passes.

Reuse: the existing Featured source and ranking, authorized Live cursor API, native save editor, shared-visit invitations, protected photo gallery, full place profile and plan composer. Do not merge, release, globally activate Live, or repeat the old full-CI runs.

Data flow: committed scope/filter → server-authorized map-page reader → complete map snapshot + bounded display count. Feed keeps its own lazy pages and history sections. Map work does not wait for Feed scrolling or optional media. Account/query changes cancel old work; errors show an incomplete result instead of an invented total.

Interaction: Featured and All time are defaults. The drawer's full-width upper segment tracks the finger immediately; only the final detent changes map framing. Photo pins retain activity badges and density dots. Native MapKit restaurants, businesses and other points of interest remain visible independently of saved activity; tapping one opens the current Astir place preview and full profile without creating a save or changing the Feed count. The preview uses vertical-only overshoot, square overlapping gallery thumbnails, top-left Close and a direct full-profile route. Plans renders cached eligible friends immediately and performs bounded refresh outside body evaluation.

Save flow: existing Wanna → prefilled complete editor → Wanna or new check-in. Remove from Wanna defaults No and applies only after successful durable check-in, preserving the original on failure. Text controls avoid unchanged attributed-text writes so selecting form answers keeps the scroll position.

Shared check-ins: only explicit accepted shared-visit identity joins posts. Same place/time is insufficient. Participant metadata comes from a narrow viewer-authorized batch contract; pending companions remain owner-only. Existing event IDs retain their engagement targets. Missing contract falls back to separate authorized posts, with installation recorded before calling the feature complete.

## Engineering/design review

Architecture/code quality: separate map completeness from 20-card display pagination; keep per-frame gestures out of data projection; reuse existing authorization and saving paths. Performance: cache friend ranking and map pin snapshots; eliminate serial full-profile hydration from opening Plans; no optional gallery download before map content. Tests: cursor exhaustion beyond 20/100, duplicate/stale/account boundaries, default filters, broad header drag geometry, save-mode preservation/removal failures, exact shared-group identity/privacy, direct full route and appearance propagation.

State coverage: map loading shows an unfinished count; empty is a true exhausted result; failed reads offer retry; new queries never show old results as final. Plans remains cancellable and shows a specific unavailable/error state. Failed Wanna removal cannot disguise a successful check-in or delete an unrelated save.

Design passes: preserve map → compact summary → Feed hierarchy; all loading/empty/error states above; smooth drag and stable form position remove interruption; no new decorative shell; use existing Signal/brand/glass tokens; retain44pt targets, Dynamic Type and Reduce Motion; user has already specified photo badges, Close placement and vertical motion. No new product choice is required before implementing these accepted directions.
