# Live review, third feedback round

REC-636 continues on `codex/rec636-review-feedback` / PR #736. Prior reported passes for round-two items 1, 2, 7, and 10 remain recorded. This round changes only the unresolved behavior below. Manual outcomes are blank until the tester reports them.

## Changes and boundaries

- Drawer release direction and physical position determine the destination. Short flicks advance a detent; a longer drag can cross more than one. Only the lightweight drawer tracks touch samples.
- Expanded place-photo pins batch metadata requests, use the shared image cache and bounded downloads, and retry transient misses. Density dots begin loading when expanded. A place with no available provider or authorized user image retains a placeholder; no substitute image is invented.
- Provider hours/open status remain independent of the image source and entrance animation.
- Plans uses a distinct demo route so it cannot intercept the production composer. Any mutual friend can be invited when an authorized save exists for the place; shared activity still determines friend ranking. Opening the composer sends nothing. Sharing retains server authorization and gives a visible error if access changes.
- The Live + entry resolves an existing own save using canonical/provider identity and a tightly bounded native-place fallback. An existing Wanna opens its populated editor, with Check-in available as a separate visit. Prior check-ins determine the map badge even when the Wanna remains or a new Wanna is added later. When a visited place has no Wanna left, Live + defaults to Check in and still offers a fresh Wanna; ordinary history editors are unchanged.
- Remove from Wanna defaults Off. When selected, it refreshes authoritative own-place/Wanna history before capturing the existing Wanna identities and starting the check-in. Incomplete or unavailable history stops submission with a connect/retry or keep-Wannas choice. After the check-in saves, only the captured Wannas are removed. New Wannas created afterward, visits and list membership are preserved. A connection loss after preparation retains a durable dependency on the replacement visit; failure leaves a visible pending message and a retryable deletion. Proven never-uploaded duplicate parents complete locally after that dependency succeeds.
- The place name stays above the scrolling save form.
- Shared postcards use explicit accepted shared-visit identity, including provable historical events. Each participant's authorized note/photos appear on the same card. The discussion reads the original posts' comments with separate cursors, and keeps original IDs, authorship, likes and deletion rules. New comments use the readable source post, otherwise a stable readable original. No historical user record is rewritten or deleted to make this presentation.

Unlinked old check-ins cannot safely be inferred to be one visit merely because people were at the same place/time. Ambiguous or inaccessible records stay separate. Supplemental shared contributions are context, not additional matches for the Feed's selected filters or count.

## Changed-only manual checks

Start with the designated first internal account. Do not send invitations or comments to ordinary users. Keep deferred review blocks separate from this round.

1. **Flick direction:** From half height, make short quick downward and upward swipes from the left, center and right of the drawer header. Each must move in the release direction. Drag past the middle detent and flick farther, then try reversing direction before release. Repeat while photos load; cards should scroll normally without moving the drawer.
2. **Photo population:** Open a busy LA area and wait for its results. Inspect more than 20 expanded pins, then zoom a dense group from dots into photo circles. Photos that are available should load without opening each place. Note any remaining placeholder's place name so an actual missing image can be distinguished from a failed request.
3. **Preview hours:** Open several places with known hours, allow the entry animation to finish, and wait for the photo. The time/open-closed field should remain. Switch quickly between places and confirm details do not carry over from the previous place.
4. **Plans destination:** Open a full place page → Plans → choose a mutual friend. The invitation editor should open promptly, including when only one of you has saved the place. Change the proposed time and note; the Share invitation control should be available once the place is synced. Use only the designated internal recipient if actually sending, and verify the resulting invitation opens for that recipient. An unavailable friendship/place should show an error rather than do nothing.
5. **Unsaved place:** Press + for a genuinely unsaved place. Both Check-in and Wanna should be available; cancel without creating data.
6. **Existing Wanna:** Use Miya Miya Shawarma and one other saved Wanna. Press + from the photo pin and from the native map place. The existing Wanna and its data should appear. Edit it and verify this updates the original rather than adding a duplicate.
7. **Wanna plus check-in:** For a place with both, verify the pin is a check-in while the Wanna remains in your history/profile. Press + and verify both modes remain available. Creating another Wanna later must not replace the check-in badge.
8. **Keep prior Wannas:** Switch an existing Wanna to Check-in. Remove from Wanna must default Off. Complete a disposable internal check-in: the new check-in and all previous Wannas should remain.
9. **Remove prior Wannas:** On a disposable place with multiple Wannas, switch to Check-in and enable Remove from Wanna. Verify its crossed-Wanna icon and switch appearance. Save; all prior Wannas should disappear from the Feed, history and profile, while visits/list membership remain. Create a new Wanna afterward: it should appear normally and the map should still show a check-in. Canceling before Save must remove nothing.
10. **Unavailable history:** On a disposable internal record, go offline and attempt a check-in with removal enabled. Submission must stop before creating the check-in or deleting anything, with an instruction to connect or turn removal Off. Reconnect and retry once. If connectivity drops after history preparation, any queued removal must wait for the replacement check-in to sync; a pending state must not claim completion.
11. **Shared postcard and comments:** Use a known accepted shared check-in. Refresh: it should appear once with each participant's own note and square photo stack. Open comments: both originals' existing comments should appear once, with authorship intact; loading earlier comments must not repeat them. With the designated second tester, add a note/photo to their accepted visit and verify it appears on the same card. An unrelated same-place check-in remains separate. A pending invitation must not disclose private participant content.
12. **Pinned title:** Open both Wanna and Check-in forms, scroll to the bottom, show/dismiss the keyboard and change a question. The place name should stay visible at the top without moving the current form position.
