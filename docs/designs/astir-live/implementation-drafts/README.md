# REC-636 implementation drafts

These are review drafts, **not installed migrations**. Neither SQL draft has been applied to hosted Supabase. The store patch is unapplied. The new app code and tests do not establish backend readiness; keep `unified_live_v1` disabled until the integration and validation below are complete.

## Package and integrate

1. Inspect the available CLI with `supabase --version`, `supabase migration new --help`, and `supabase db push --help`. Review the linked target and its migration history before any hosted change.
2. Run `supabase migration new private_contextual_messages` first. Copy the reviewed SQL from [private-contextual-messages.sql](private-contextual-messages.sql) into the **CLI-generated file**, replacing its draft-status comments when it becomes a migration. This creates the private messaging schema/RPCs and registers the dormant Boolean `unified_live_v1` while preserving existing flag keys and ranges.
3. Run `supabase migration new live_activity_feed` second. Put [live-feed.sql](live-feed.sql) into that CLI-generated file. It adds the Live query RPC, polygon validator, and time index without replacing existing Feed APIs or visibility helpers. Review both generated files together; do not invent migration filenames or apply these documentation drafts directly.
4. Review [store.patch](store.patch). `git apply --check docs/designs/astir-live/implementation-drafts/store.patch` passes against the reviewed checkout. After the shared-store integration is authorized, apply it, then regenerate with `xcodegen generate`. The patch adds the Feed-only query seam plus five `LiveFeedStoreTests`; it does not change Profile history or shared-cache policy. Recheck the patch against intervening source changes before applying.
5. First extend the query model, RPC parameters, pre-limit predicates and cursor fingerprint for the accepted radius/category/person facets; the current draft covers time/type/polygon only. Add matching native and SQL tests. Then bind committed Live controls to `selectLiveFeedQuery(_:)`, then call `refreshFollowedFeed(backend:force:)`. Keep the date window fixed across pagination. Explicit `nil` restores the legacy API; ordinary tab switching must not reset the selected query. Reject invalid or hemispheric polygons before submitting them.
6. Review the migration target and change set, apply through the migration workflow, verify `supabase migration list --linked`, then run metadata/security checks and the smoke suites. Activation is a separate full-launch feature-flag decision.

## Messaging release boundaries

- Messages are mutual-friends-only 1:1 text. There are no attachments, groups, presence, realtime subscriptions, or message notification delivery. The initial screen refresh, pagination, and send/read responses are authoritative. Pending or ambiguous sends retain the same client-generated idempotency UUID.
- The repository is memory-only. Its dedicated ephemeral HTTP transport disables URL caching and cookies and never logs request bodies, response bodies, or raw backend errors. UI replay masking and account/lifecycle clearing require their native integration checks.
- Each operation rechecks participants, current mutual friendship, hard blocks, and source access. Context titles are resolved at read time. A revoked or deleted context suppresses its contextual message, preview, and unread count; unrelated private follow-on text remains subject to conversation eligibility.
- **Account-deletion retention is a broad-rollout blocker requiring a product decision.** Soft-deleted accounts immediately lose thread access, but existing message rows remain stored. Physical profile deletion cascades through conversations and messages. No additional soft-delete purge or retention period is introduced by these drafts.
- Message reporting/moderation and retention/export behavior need an explicit rollout decision. Existing profile blocking remains available; no report-message workflow or abuse-retention policy is added here. The server provides basic 20/minute and 200/day send limits plus 50 new conversations/day; operational tuning and authenticated hosted checks remain required.
