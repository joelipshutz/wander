# REC-80 Rating Editing QA Plan

Generated by `/plan-eng-review` on 2026-07-09.
Branch: `codex/rec-80-rating-edit-plan`
Linear: `REC-80`

## Affected Screens

- Map selected place sheet — verify the primary saved-place action no longer implies there is only one rating.
- Place profile full screen — verify `latest activity` and `MY VISITS` show separate visit cards.
- Add flow — verify first-time `Been` save still asks for a rating and creates the first visit.
- Visit editor sheet — verify add/edit/delete visit actions own rating, note, tags, and visibility.

## Key Interactions To Verify

- Save a new place as `Been`, set rating to `4.5`, and confirm one map pin plus one visit card.
- Add a second visit to the same place with rating `2.5`, and confirm the first visit remains `4.5`.
- Edit the first visit rating to `5`, and confirm the second visit stays `2.5`.
- Open generic `Edit this place` for an existing saved place, and confirm rating editing is not there.
- Delete one visit, and confirm the place remains saved if another visit exists.
- Remove the saved place, and confirm all of the current user's visits disappear.

## Edge Cases

- `Wanna go` save should not create a rated visit or affect recommended score.
- Private/self-only visit should not leak to another user's social activity or aggregate.
- Offline add/edit visit should remain local with visible pending sync state.
- Old server payloads with no visit array should decode without crashing during rollout.

## Critical Paths

- First-time save: user creates saved-place shell and first visit in one action.
- Repeat visit: user adds another memory without overwriting the previous rating.
- Social proof: friends' multiple visits contribute to ratings without duplicating the map pin.
- Sync: local pending visits eventually sync or surface an actionable error.
