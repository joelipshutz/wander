# Place Profile Redesign Test Plan

Generated by `/plan-eng-review` on 2026-06-24
Branch: `codex/place-profile-eng-review`
Repo: `joelipshutz/wander`

## Affected Screens

- Map selected-place preview: verify unsaved trusted, unsaved thin, and saved states.
- Full place profile: verify saved-by-you, unsaved with trusted signal, and unsaved thin signal.
- Discover place detail entry point: verify it uses the same profile semantics as Map.
- Profile saved-place rows/details: verify city/status text, rating display, and edit path.

## Key Interactions To Verify

- Tap a map pin for an unsaved place with trusted ratings: preview shows plus + share, trusted rating, city/category line, and no full address.
- Open full profile from preview: bottom tabs remain visible; action row appears above `Why it fits`.
- Save an unsaved place from the plus action: save/edit flow captures rating only for `Been`.
- Open a saved place: top actions are edit + share, not plus; `Your note` appears with own rating.
- Open a thin-signal place: no fabricated fit or trusted rating; empty rating state is quiet.

## Edge Cases

- Remote place has no locality: profile row must not default to `Los Angeles`.
- Remote place has no website or phone: Website and Call buttons are hidden.
- Place has one tag from one person only: tag should not appear as common.
- Place has two trusted matching tags: tag appears in common tags.
- User has too few rated places: fit rating is hidden, but `Why it fits` can still show generic category/location context.
- `wanna_go` save has no numeric rating and does not affect trusted aggregate.

## Critical Paths

- Actual rating: saved-by-you shows own explicit rating; unsaved shows trusted aggregate when available.
- Fit rating: deterministic helper returns a 0-10 score only when evidence is strong enough.
- Common tags: repeated structured attributes produce horizontal tags without note/LLM parsing.
- Remote metadata: RPC/DTO hydrates city/address/action fields before full profile depends on them.
- Regression: profile rows do not show false city names when locality is missing.
